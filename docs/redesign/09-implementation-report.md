# HabileSec rebuild — implementation report

Implementation date: 28 October 2026. This report supersedes the unimplemented visual proposal in Phase 1. Work is local to Habilesec; nothing was deployed.

## Implemented experience

The active route tree uses original components in components/rebuild, a fresh app/globals.css, and reviewed content in content/rebuild.json. The old components and data remain on disk but are not imported by active pages. The design uses ice-blue, mist-blue and medium-blue surfaces with dark text and contrast-corrected link/control colors. Instrument Sans headings and Plus Jakarta Sans body copy are self-hosted through next/font/local. No dependencies were installed or changed. Lightweight interaction data is generated by scripts/rebuild-sync.mjs into content/rebuild-interactive.json; run that script after editing the main business snapshot. Full article bodies are excluded from compiled client chunks, and the insights filter receives preview fields only.

Page coverage: home; seven service categories; 26 capability records with distinct detail routes; GRCLoop, ForgeLoop and HexN6 practices; product index and Tanikkai/Certanika Lite pages; six source-backed industries; About; Contact; 15 published article details and searchable listing; six engagement overviews and listing; FAQ; testimonials; group-company network; privacy, terms and fair-labor pages. Legacy service, industry, case-study and known article-ID destinations have explicit redirects. Unsupported target-only sectors point to the verified industry directory rather than receiving invented content.

Interactions: desktop services mega-menu and products disclosure; mobile navigation; active-route indication; Escape dismissal and focus return; keyboard product/industry tabs; manually controlled testimonials; insight search/category filter; native FAQ disclosure; form validation and status announcements; restrained entry transitions and reduced-motion support. The mobile hero follows content height naturally. All substantive article content is rendered as escaped text in semantic headings/paragraphs; source HTML cannot execute.

## Contact integration and remaining setup

The target previously prepared a mailto draft. The replacement POST /api/contact validates fields, enforces same-origin browser submissions, limits JSON body size while reading the stream, rejects the honeypot, applies a bounded per-process rate limit and proxies the existing EX backend contract at /api/contact/create. Server-only configuration: HABILESEC_BACKEND_ORIGIN (or existing BACKEND_ORIGIN). Use the Express backend origin, not this frontend origin. No credentials or private enquiry records were read or copied.

The form shows success only after an explicit upstream success result. Notification failure after saved persistence does not trigger a false failure, and the old second EmailJS delivery is not duplicated. An ambiguous upstream failure tells the visitor to contact the company before retrying. Without backend configuration it returns 503 and presents verified email/phone alternatives. This is an explicit incomplete production connection, not a claim that email was delivered.

Local tests use a separate localhost mock. No production enquiry or email was sent. Production backend/mail delivery still requires environment configuration and a controlled deployment verification. The in-process rate limit is best-effort; the retained backend/proxy must enforce production abuse controls across instances.

Public content is a reviewed snapshot dated 2026-10-28. The EX CMS/admin, draft preview, uploads, subscriptions and chatbot were not migrated into the target: they were absent from the target and remain untouched in EX. CMS changes do not automatically update this snapshot. Production hosting must preserve any independently served product path such as /Certanika-Lite.
